# ไก่เฮงเฮง — ระบบสั่งข้าวมันไก่และจัดการคิว

เว็บร้านข้าวมันไก่ภาษาไทยที่มีทั้งหน้าลูกค้า ระบบคิว และหลังบ้านร้านค้าในโปรเจกต์เดียว ออกแบบสำหรับเก็บซอร์สบน GitHub และนำไปรันบน Cloudflare Workers พร้อม D1 และ R2

> GitHub Pages ใช้โฮสต์โปรเจกต์นี้ไม่ได้โดยตรง เพราะ GitHub Pages รองรับเฉพาะเว็บแบบ Static แต่ระบบนี้ต้องมี API, ฐานข้อมูล, การล็อกอิน และพื้นที่เก็บรูป ใช้ GitHub เป็นที่เก็บซอร์ส แล้วเชื่อมกับ Cloudflare หรือ OpenAI Sites เพื่อ Deploy

## ความสามารถหลัก

- หน้าร้าน Responsive สำหรับมือถือ แท็บเล็ต และคอมพิวเตอร์
- เมนูเริ่มต้น: ข้าวมันไก่ต้ม และข้าวมันไก่ทอด
- ตะกร้าและแบบฟอร์มสั่งอาหาร
- ออกเลขคิวรายวันโดยอัตโนมัติ
- หน้าติดตามสถานะที่อัปเดตทุก 5 วินาที
- สถานะ: รับออเดอร์ → กำลังทำ → พร้อมรับ → ส่งมอบแล้ว
- หลังบ้านแบบ PIN พร้อมคุกกี้ที่ลงลายเซ็นและเก็บแบบ HttpOnly
- Kanban ออเดอร์สดสำหรับครัว
- สรุปยอดขายรายวัน รายเดือน และกราฟ 7 วัน
- เมนูขายดีและประวัติการสั่งซื้อ
- เพิ่ม แก้ไข ลบ เปิด–ปิดเมนู และเปลี่ยนราคา
- อัปโหลดรูปเมนูใหม่ได้จากหลังบ้าน
- Audit log สำหรับการเปลี่ยนเมนูและสถานะออเดอร์

## เทคโนโลยี

- Next.js API + React ผ่าน Vinext
- Cloudflare Workers
- Cloudflare D1 สำหรับเมนู ออเดอร์ คิว และรายงาน
- Cloudflare R2 สำหรับรูปเมนูที่แอดมินอัปโหลด
- Drizzle ORM สำหรับ Schema และ Migration
- TypeScript

## เริ่มใช้งานบนเครื่อง

ต้องใช้ Node.js 22.13 ขึ้นไป และ pnpm

```bash
pnpm install
pnpm dev
```

เปิด `http://localhost:3000`

- หน้าร้าน: `/`
- ติดตามคิว: `/track`
- หลังบ้าน: `/admin`
- PIN ทดลองบน localhost: `2468`

ข้อมูลทดลองบนเครื่องเก็บในพื้นที่ Local ของ Wrangler และไม่ถูก Commit ขึ้น GitHub

## ตั้งค่าระบบจริง

กำหนด Environment Variables ในระบบ Hosting:

```text
ADMIN_PIN=รหัสที่ร้านกำหนด
SESSION_SECRET=ข้อความสุ่มยาวอย่างน้อย 32 ตัวอักษร
```

อย่า Commit ค่าจริงลง GitHub

Bindings ที่โปรเจกต์ต้องใช้:

```json
{
  "d1": "DB",
  "r2": "MENU_IMAGES"
}
```

ระบบ Hosting จะสร้างและเชื่อม D1/R2 ตาม `.openai/hosting.json` และใช้ Migration ใน `drizzle/`

## คำสั่งสำคัญ

```bash
pnpm dev          # เปิดเว็บสำหรับพัฒนา
pnpm build        # สร้างเวอร์ชัน Deploy
pnpm db:generate  # สร้าง Migration หลังแก้ db/schema.ts
pnpm lint         # ตรวจรูปแบบโค้ด
```

## โครงสร้างข้อมูล

- `menus` — เมนู ราคา รูป ลำดับ และสถานะเปิดขาย
- `orders` — เลขคิว ลูกค้า สถานะ ยอดเงิน และเวลา
- `order_items` — รายการอาหารในแต่ละออเดอร์
- `queue_counters` — ตัวนับคิวแยกตามวัน
- `audit_logs` — ประวัติการแก้ไขที่สำคัญ

ราคาที่ลูกค้าเห็นจะถูกคำนวณซ้ำที่ฝั่งเซิร์ฟเวอร์ก่อนบันทึกเสมอ ลูกค้าจึงแก้ราคาเองจากหน้าเว็บไม่ได้

## ก่อนเปิดร้านจริง

1. เปลี่ยนชื่อร้าน เบอร์โทร เวลาเปิด และข้อความในหน้าเว็บ
2. ตั้ง `ADMIN_PIN` และ `SESSION_SECRET`
3. อัปโหลดรูปเมนูจริงจากหน้า Admin
4. ทดลองสั่งและเปลี่ยนสถานะครบหนึ่งรอบ
5. ตรวจนโยบายความเป็นส่วนตัวและข้อกำหนดการเก็บเบอร์โทรตามรูปแบบธุรกิจของร้าน
